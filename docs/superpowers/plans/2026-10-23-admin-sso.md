# Admin SSO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add multi-connection OIDC, OAuth2 and SAML login to NPM administration with a shared email allowlist, existing user permissions and immediate SSO session revocation.

**Architecture:** A shared SSO service performs admission, account linking and session creation after protocol adapters validate identity. Persist browser transactions, handoffs and login sessions; reference sessions from application JWTs and enforce their source through API, refresh and streaming paths. Reconcile the current frontend permission contract with backend capabilities rather than create an SSO authorization system.

**Tech Stack:** Existing Go/Chi/GORM/polyschema, React/TypeScript/Vite/Tabler, Vitest/Testing Library and Cypress. Use `golang.org/x/oauth2` already in the repo, `github.com/coreos/go-oidc/v3/oidc`, and `github.com/crewjam/saml`; pin audited compatible releases during Task 7, not floating branches. Use standard-library AES-GCM for secret storage.

**Spec:** [Approved design](../specs/2026-10-23-admin-sso-design.md). Read it and root `AGENTS.md` before execution. This document is a plan, not evidence that any product test has run.

## Global Constraints

- Preserve bootstrap: create the first local administrator, log in, then configure SSO.
- Support parallel password/SSO login and SSO-only mode.
- One shared allowlist of complete email addresses applies to every enabled connection. No domain rules, per-user connection assignments or per-connection allowlists.
- SSO bypasses NPM 2FA. Password login retains its existing 2FA behavior.
- Logout ends the NPM session only; no provider logout or single logout.
- Disabled users remain blocked. Never reactivate or grant permissions as a side effect of SSO.
- Newly created SSO users receive zero capabilities.
- Removing an email immediately revokes its SSO sessions but does not disable the user or their permitted password login.
- Disabling a connection immediately revokes sessions originating from that connection. Other connections and password sessions remain unaffected.
- All three protocols and multiple simultaneously enabled connections are in the first release.
- Follow root AGENTS.md: Go formatting, tabs/frontend Biome conventions, regression tests, and supported SQLite/Postgres/MySQL migrations. Never edit an applied migration.
- Work in an isolated checkout at execution time. Preserve untracked `.idea/` and `AGENTS.md`; commit only explicit task files. Do not deploy or introduce unrelated repairs.

## Review Focus

1. Simultaneous first logins and differently cased existing emails must resolve to one live user without granting permissions (Tasks 2 and 6).
2. Disable/remove racing with callback, refresh, handoff exchange or an open stream must not create a surviving SSO session (Tasks 3, 6 and 10).
3. Real SAML cross-site POSTs, two tabs and shared NAT must retain the correct browser/connection binding (Tasks 7 and 9).
4. Old JWTs, old OAuth routes, generic settings writes and debug endpoints must not bypass new admission or permission checks (Tasks 4 and 11).
5. Restore without the encryption key, stale edit forms and provider metadata/signing-key rotation must fail explicitly without leaking secrets or reviving sessions (Tasks 2, 5 and 12).

## Shared contracts

Backend contracts are defined once here. Avoid import cycles: entity packages never import the service, API or `serverevents`; the SSO service may import entity/user and entity/session; HTTP handlers orchestrate service results. `entity/session` may read `entity/sso`, but `entity/sso` must not import `entity/session`. Both use independent `internal/authpolicy` fencing. Administration handlers coordinate session revocation inside the same fenced transaction as configuration mutations.

```go
// internal/entity/sso
type Protocol string // "oidc", "oauth2", "saml"
type LoginMode string // "parallel", "sso_only"
type Policy struct { Mode LoginMode; PublicURL string; Revision uint64 }
type Connection struct {
    ID string; Protocol Protocol; Name string; Enabled bool
    Revision uint64; ConfigJSON string; SecretCiphertext []byte
}
func NormalizeEmail(raw string) (string, error)
func WithPolicyWrite(ctx context.Context, fn func(tx *gorm.DB) error) error

// internal/entity/session
type Source string // "local", "ldap", "sso", "impersonation"
type Model struct {
    ID string; UserID uint; Source Source
    ConnectionID string; LoginEmail string; ParentID string
    CreatedAt time.Time; ExpiresAt time.Time; RevokedAt *time.Time
}
type Principal struct { Session Model; Capabilities []string }
func Create(tx *gorm.DB, value Model) error
func Authorize(ctx context.Context, id string, now time.Time) (Principal, error)
func Revoke(ctx context.Context, id string, now time.Time) error
type RevocationFilter struct { SessionID, ConnectionID, LoginEmail string }
func RevokeMatching(tx *gorm.DB, filter RevocationFilter, now time.Time) error
func WithAuthorizedDelivery(ctx context.Context, id string, deliver func(Principal) error) error

// internal/sso
type Identity struct { Subject, Email, Name string }
type Transaction struct {
    ID, ConnectionID, BrowserHash, StateHash, Nonce, PKCEVerifier, RequestID string
    State string // transient plaintext for outbound request only; persist StateHash
    ConnectionRevision uint64; ReturnPath string; ExpiresAt time.Time
}
type StartResult struct { RedirectURL string }
type Adapter interface {
    Start(context.Context, ssoconfig.Connection, Transaction) (StartResult, error)
    Complete(context.Context, ssoconfig.Connection, Transaction, *http.Request) (Identity, error)
}
// ssoconfig is an import alias for npm/internal/entity/sso.
type Service struct { /* injected database, clock, entropy, secret store, adapters */ }
func (s *Service) Begin(ctx context.Context, connectionID, browserToken, returnPath string) (StartResult, error)
func (s *Service) Complete(ctx context.Context, connectionID, browserToken string, r *http.Request) (string, error) // returns handoff code
func (s *Service) Exchange(ctx context.Context, code, browserToken string) (session.Model, error)
```

Use random 32-byte base64url opaque IDs/tokens; persist SHA-256 hashes for browser binding, state and handoff lookup. Encrypt transaction nonce/verifier/request material at rest as needed through the secret store. Login transactions expire after 5 minutes; handoffs after 60 seconds; replay identifiers are retained through the original assertion expiry plus 2 minutes. Use injectable clocks, not test sleeps. Application JWT lifetime stays at the current 24 hours; SSE JWTs expire in 60 seconds and never outlive the parent session. Expired/revoked sessions never refresh. Active sessions use the existing rolling refresh behavior while retaining the same ID and source; changing their idle/absolute policy is out of scope.

Database policy mutations, admission and stream delivery serialize through one persistent `auth_policy_fence` singleton row. PostgreSQL/MySQL use a transaction updating the row; SQLite uses its write-transaction equivalent with bounded busy retry. Reads used for authorization must be fresh committed reads, not a stale repeatable-read snapshot or TTL cache. `WithPolicyWrite` delegates to this fence. Lock order: fence Ã¢â€ â€™ connection/allowlist Ã¢â€ â€™ user Ã¢â€ â€™ session; use the same order everywhere.

Public JSON is snake_case on the wire and camelCase through existing frontend API conversion. Use current API response envelopes. Errors use stable codes plus localized UI copy; omit provider response bodies, raw assertions, credentials and account-existence hints.
