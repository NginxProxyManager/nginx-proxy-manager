# Task 7 report

Status: implemented and verified. No deployment. Task 7 plan checkboxes remain for parent review.

## Implementation

- Added `NewProviderClient()` with a 10-second total timeout, a 1 MiB response-body cap, HTTPS-only requests, and same-origin redirects. `NewOIDCAdapter(client, secrets)` rewraps an injected client's transport so its timeout, redirect policy and body limit cannot be relaxed by that client. Tests can supply a fixture TLS transport; production uses normal TLS verification. Provider response bodies and transport error strings are replaced with `ErrDenied` at the adapter boundary.
- Added the OIDC adapter using `oidc.NewProvider`, the library verifier, OAuth2 authorization code exchange, S256 PKCE, transaction state and nonce. It explicitly validates `azp` for multiple audiences and any present `azp`, validates ID-token/UserInfo subject equality, and reads only nonempty scalar claims. It does not fabricate email or require `email_verified`. Default scopes are `openid email profile`. Client-secret basic is the default; configured post is explicit, without auth-style probing. The client secret is unsealed from the encrypted JSON bundle with AAD `connection:<id>`.
- Added transient `Transaction.PublicURL` to the shared adapter contract. Service Begin and Complete load and validate the policy origin inside their fenced reads, and adapters derive callback URLs from it. OIDC uses `{public_url}/sso/{connection_id}/callback`. The public origin is never taken from request Host. The field is not persisted in the transaction secret material. A `Probe(context, connection)` method is available for Task 11 to register through `handler.RegisterSSOProbe` without an import cycle; it performs bounded read-only discovery, with no login/user/session creation.
- Tightened OIDC `issuer_url` validation to reject query, bare `?`, and fragment while retaining path support. OIDC rejects insecure advertised authorization or token URLs.
- Added standalone `test/ssofixtures` Go module and HTTPS OIDC executable. Run `go run . --listen 127.0.0.1:0 --cert-out <path> --key-out <path> --case valid`; it emits JSON containing issuer URL, fixture client credentials and CA certificate path. It generates a new self-signed loopback certificate and credentials each process start, writes the private key mode 0600, and binds only loopback. Separate processes provide two distinct IdP origins for Task 15 without global trust changes. Cases: valid, signature, issuer, audience, azp, nonce, expired, userinfo_subject, email_array, email_missing, rotation. Rotation exposes `POST /rotate` to switch JWKS from old to current signing key. The executable supports browser authorization redirect, code exchange with PKCE, JWKS and UserInfo. `use_userinfo: true` is needed to exercise the UserInfo subject case.
